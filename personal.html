개요 및 학습 목표

3분

이런 상황, 익숙하시죠?

입사일은 다가오는데 장비 신청표에는 "연동미완료", "재고확인중", "승인대기"가 섞여 있습니다. 누가 급한지 매번 날짜를 세고, 비고를 하나하나 읽어 담당자에게 물어봐야 합니다. 이번 실습에서는 표를 넣기만 하면 급한 순서대로 막힌 이유와 다음 할 일을 정리해 주는 스킬을 씁니다.

학습 목표

  • 스킬 파일을 열어 우리 팀 규칙을 직접 더하기
  • 스킬 zip을 업로드해서 설치하기
  • 채팅에서 스킬을 불러 실행하기
  • 결과를 체크리스트로 검증하기 (AI 결과를 그대로 믿지 않는 습관)

Step 1내려받은 zip 풀기

폴더 이름을 바꾸지 마세요

폴더 이름이 스킬 이름입니다. 같은 이름의 폴더가 이미 있어 gs-equipment-check 2처럼 생기면, 이전 폴더를 지우고 다시 풀어 주세요.

Step 2우리 팀 규칙 2줄 더하고 다시 압축하기

남이 만든 스킬도 우리 팀 상황에 맞게 고쳐 쓸 수 있어야 합니다. 이 실습 데이터에는 재고 정보가 시트끼리 서로 다르게 적혀 있어서, AI가 "재고 충분/부족"을 단정하면 틀릴 수 있습니다.

  1. SKILL.md를 오른쪽 클릭 → 다음으로 열기 → 텍스트 편집기(Windows는 메모장)
  2. 맨 아래 ## 규칙 목록 끝에 아래 두 줄을 붙여 넣고 저장합니다. (확장자를 묻으면 .md 유지)
  3. Finder에서 gs-equipment-check 폴더를 오른쪽 클릭 → "gs-equipment-check" 압축을 누릅니다. (Windows: 오른쪽 클릭 → 압축(ZIP) 폴더)
규칙에 추가할 2줄
- 비고에 '재고'라는 말이 있으면 재고가 충분한지 부족한지 단정하지 말고 "재고 정본 확인 필요"로 표시한다.
- 표에서는 성명보다 신청번호를 먼저 쓰고, 안내문 초안 외에는 개인 이름을 반복하지 않는다.
새로 만든 gs-equipment-check.zip을 열었을 때 맨 위에 폴더가 있고, 그 안에 SKILL.md가 있으면 맞습니다. 파일이 zip 맨 위에 바로 있으면 업로드가 안 됩니다.

업로드 메뉴가 안 보이면 Work 대화에 SKILL.md를 첨부하고 "이 파일 내용 그대로 gs-equipment-check 스킬로 설치해줘"라고 요청한 뒤, 뜨는 창에서 Install을 누르세요.

  • 스킬 이름은 영문 소문자와 하이픈(-)만 씁니다.
  • Step 2를 건너뛰고 원본 zip을 그대로 올려도 설치는 됩니다. 다만 체크리스트 ⑤번이 다르게 나옵니다.

💬 프로젝트가 왜 "노코드 에이전트"인가요?

프로젝트는 파일(지식) + 지침(규칙)을 한곳에 묶어 두는 공간입니다. 그 안에서 시작하는 모든 대화가 같은 자료와 규칙을 따르니, 코딩 없이 우리 팀 전담 비서를 만든 것과 같습니다. 이번에는 데이터뿐 아니라 "어떤 데이터를 믿고, 모르면 어떻게 말할지"까지 지침으로 알려 줍니다.

프로젝트 지침
당신은 카카오 총무팀의 '총무 데이터 컨시어지'입니다. 이 프로젝트에 올린 파일만 근거로 한국어로 답합니다.

[데이터의 성격]
- 장비 신청표: 장비 신청·지급상태의 정본. 인사시스템 연동여부는 인사시스템의 사본이므로 "시트 기준"이라고 밝힌다.
- 좌석 현황표: 좌석 배치의 정본. 신규 입사자 좌석은 들어 있지 않다.
- 예산 정산표: 전자결재의 작업본. 오른쪽 요약표는 검산 대상이지 근거가 아니다.
- 지식 카드: 시트에 없는 맥락. 신뢰도 '낮음' 카드는 단독 근거로 쓰지 않는다.

[답변 원칙]
1. 첫 줄에 [기준일]. 사용자가 말하지 않으면 2026-11-23.
2. 숫자마다 근거(파일, 행, 계산식)를 붙인다.
3. 충돌은 고르지 않는다. '충돌 미해결' 카드의 내용은 양쪽을 모두 전달한다.
4. 기준이 두 개면 둘 다 보여준다. 예: 집행률은 장부 기준(집행금액 전체)과 지급 기준(지급완료만).
5. 파일에 없으면 "근거 없음". 조직개편으로 둘로 갈라진 부서의 입사자 소속은 "확정 불가".
6. 결재·발주·발송은 하지 않는다. 안내문과 공지는 초안으로만 쓰고, 다른 직원 이름 대신 부서 단위로 쓴다.
