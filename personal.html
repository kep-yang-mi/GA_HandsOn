개요 및 학습 목표

3분

이런 상황, 익숙하시죠?

입사일은 다가오는데 장비 신청표에는 "연동미완료", "재고확인중", "승인대기"가 섞여 있습니다. 누가 급한지 매번 날짜를 세고, 비고를 하나하나 읽어 담당자에게 물어봐야 합니다. 이번 실습에서는 표를 넣기만 하면 급한 순서대로 막힌 이유와 다음 할 일을 정리해 주는 스킬을 씁니다.

학습 목표

  • 스킬 파일(.md)을 업로드해서 바로 설치하기
  • 스킬 지침을 열어 우리 팀 규칙을 직접 더하기
  • 채팅창에서 / 명령으로 스킬을 불러 실행하기
  • 결과를 체크리스트로 검증하기 (AI 결과를 그대로 믿지 않는 습관)

Step 1파일 업로드로 스킬 설치하기

  1. 왼쪽 메뉴에서 스킬(Skills)을 클릭합니다.
  2. 오른쪽 위 ＋ → 스킬 업로드(Upload skill)를 클릭합니다.
  3. 내려받은 gs-equipment-check.md를 끌어다 놓거나 파일 찾아보기로 선택한 뒤 가져오기를 누릅니다.
스킬 목록 사용 설정됨(Enabled)에 gs-equipment-check가 보이면 성공입니다.

Step 2스킬 지침에 우리 팀 규칙 2줄 더하기

남이 만든 스킬도 우리 팀 상황에 맞게 고쳐 쓸 수 있어야 합니다. 이 실습 데이터에는 재고 정보가 시트끼리 서로 다르게 적혀 있어서, AI가 "재고 충분/부족"을 단정하면 틀릴 수 있습니다.

  1. 스킬 목록에서 gs-equipment-check를 클릭해 편집 화면을 엽니다.
  2. 지침 맨 아래 ## 규칙 목록 끝에 아래 두 줄을 붙여 넣습니다.
  3. 오른쪽 위 저장(Save)을 누릅니다.
규칙에 추가할 2줄
- 비고에 '재고'라는 말이 있으면 재고가 충분한지 부족한지 단정하지 말고 "재고 정본 확인 필요"로 표시한다.
- 표에서는 성명보다 신청번호를 먼저 쓰고, 안내문 초안 외에는 개인 이름을 반복하지 않는다.

Step 3이름 확인 후 저장하기

  • 저장 전에 위쪽 이름 칸이 gs-equipment-check인지 확인합니다.
  • 스킬 이름은 영문 소문자와 하이픈(-)만 씁니다. 한글이나 띄어쓰기가 들어가면 / 목록에서 찾기 어렵습니다.

초안 생성 프롬프트
첨부한 총무 데이터 3종(신규입사자 장비신청, 좌석배치 현황, 예산정산), 지식 카드 3장, 규칙 문서(AGENTS_총무팀.md)를 근거로 총무팀 동료의 질문에 답하는 '총무 데이터 컨시어지' 채팅 에이전트를 만들어줘.

- 파일끼리 내용이 다르면 하나를 고르지 말고 둘 다 보여준다.
- 파일에 없는 내용은 지어내지 말고 '근거 없음'이라고 답한 뒤 누구에게 확인할지 안내한다.
- 결재, 발주, 메시지 발송은 하지 않고 초안까지만 쓴다.

당신은 카카오 총무팀의 '총무 데이터 컨시어지'입니다. 지식(Knowledge)에 연결된 파일만 근거로 한국어로 답합니다.

[데이터의 성격]
- 장비 신청표: 장비 신청·지급상태의 정본. 인사시스템 연동여부는 인사시스템의 사본이므로 "시트 기준"이라고 밝힌다.
- 좌석 현황표: 좌석 배치의 정본. 신규 입사자 좌석은 들어 있지 않다.
- 예산 정산표: 전자결재의 작업본. 오른쪽 요약표는 검산 대상이지 근거가 아니다.
- 지식 카드: 시트에 없는 맥락. 신뢰도 '낮음' 카드는 단독 근거로 쓰지 않는다.

[답변 원칙]
1. 첫 줄에 [기준일]. 사용자가 말하지 않으면 2026-11-23.
2. 숫자마다 근거(파일, 행, 계산식)를 붙인다.
3. 충돌은 고르지 않는다. '충돌 미해결' 카드의 내용은 양쪽을 모두 전달한다.
4. 기준이 두 개면 둘 다 보여준다. 예: 집행률은 장부 기준(집행금액 전체)과 지급 기준(지급완료만).
5. 파일에 없으면 "근거 없음". 조직개편으로 둘로 갈라진 부서의 입사자 소속은 "확정 불가".
6. 결재·발주·발송은 하지 않는다. 안내문과 공지는 초안으로만 쓰고, 다른 직원 이름 대신 부서 단위로 쓴다.

Step 1Workflow Builder 열기

  1. 에이전트(Agents) → ＋ 새 에이전트 → 워크플로(Workflow)를 선택합니다.

Step 2커넥터 켜고, 프롬프트로 4단계 뼈대 만들기

  1. Google Drive와 Gmail 커넥터가 연결되어 있는지 확인합니다. (처음이면 권한 허용 창이 뜹니다)
  2. 아래 프롬프트를 붙여 넣어 뼈대를 만듭니다.
뼈대 생성 프롬프트
'총무 주간 점검 브리핑' 워크플로우를 만들어줘.
1단계 트리거: 테스트용 수동 실행. 입력 필드는 '기준일' 하나 (기본값 2026-11-23).
2단계 자료 수집: Google Drive에서 '[실습] 신규입사자 장비신청'과 '[실습] 좌석배치 현황' 시트를 읽는다.
3단계 브리핑 작성: 장비 위험 건, 좌석 재배치 진척과 막힌 좌석, 확인이 필요한 질문을 정리한다.
4단계 발송: 작성한 브리핑을 Gmail로 나에게만 보낸다. 제목은 '[총무 주간 점검] 기준일 YYYY-MM-DD'.

Step 3① 트리거 입력 필드 점검

수동 트리거에 기준일 입력 필드가 있고 기본값이 2026-11-23인지 확인합니다. 테스트 결과를 체크리스트와 맞추려면 날짜를 고정해야 합니다.

Step 4② 자료 수집 단계 점검

수집 단계가 두 시트를 모두 읽도록 되어 있는지 확인합니다. 하나만 잡혀 있으면 파일 선택에서 나머지 시트를 추가합니다.

Step 5③ 브리핑 작성 단계 지침 넣기

작성 단계를 클릭하고 지침을 아래 내용으로 바꿉니다. Step 1 스킬의 위험 기준과 Step 2 에이전트의 원칙을 합친 것입니다.

작성 단계 지침
입력받은 기준일로 두 시트를 점검해 총무팀 주간 브리핑을 작성한다.

[장비]
- 긴급: 입사까지 14일 이내 + 지급완료 아님 + (연동미완료·오류확인필요·재고확인중·승인대기 중 하나)
- 주의: 입사까지 15~30일 + 위 조건 중 하나
- 건마다 "신청번호 | 입사일(D-n) | 막힌 이유 | 다음 할 일" 한 줄. 막힌 이유는 비고에 적힌 내용만 쓴다.
- 비고에 '재고'가 있으면 "재고 정본 확인 필요"로 표시한다.

[좌석]
- 이동 대상 중 배치완료 비율 (전체 좌석 기준과 구분해서)
- 조율중 좌석마다 "좌석코드 | 정해야 할 것"

[형식]
첫 줄: 기준일 / 한눈 요약 3줄 / 장비 표 / 좌석 표 / 확인이 필요한 질문
개인 이름 대신 신청번호와 좌석코드를 쓴다. 시트에 없는 내용은 만들지 않는다.

Step 6④ 발송 단계: 받는 사람 확인

Gmail 발송 단계의 받는 사람이 나 혼자인지 꼭 확인합니다. 팀 메일 주소나 다른 사람이 들어가 있으면 지웁니다.
